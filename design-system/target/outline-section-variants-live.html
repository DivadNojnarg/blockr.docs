Section gestures, side by side and live

The same four-block board in four panes. Each pane offers a different way to start a chapter, driving the same underlying operation — so the outcome is identical everywhere and only the gesture differs. Click around; use each pane's reset.

A — pill on the boundary

Hover the outline: a dashed pill sits in every gap. Clicking it cuts there — the blocks below become a new chapter.

A — hover the card, click a pill

B — link in the block row recommended

Hover a block: "New chapter" sits beside "Add block", in the row that already holds every block-scoped action. Nothing else uses that target.

B — hover a block row, click "New chapter"

C — drag into the gap collides

Drag a chip by its grip. Both meanings appear at once: the blue line ("reorder here") and the green zone ("new chapter here") compete for the same space — this is the collision, shown rather than described.

C — drag a chip; watch the two meanings overlap

D — chapter action "split below"

A fourth hover action on the chapter row. It can only cut at one fixed place (after the chapter's first block), so it cannot express "start a chapter here".

D — hover a chapter heading, click "split below"

Also shown in every pane

The already-implemented chapter actions are live too: merge up (removes a boundary) and ungroup (dissolves the chapter, blocks stay). Try creating a chapter, then merging it back — the pair is exact.

What pane C demonstrates: a gap cannot mean two things. Any drag-based creation needs a modifier or a separate lane, both invisible — which is why the proposal is to keep drag for position/membership only.
Still missing everywhere: taking a single block out of its chapter without dissolving the whole thing. Under the same rule it would be a third link in the block row ("no chapter") rather than another drop target.
