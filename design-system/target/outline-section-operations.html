Sections in the outline — the complete operation set

Chapter management has grown piece by piece; this page puts every operation on one page so the gestures can be settled as a system rather than one at a time. The trigger was a real collision: dragging a chip into a gap already means "reorder here", so it cannot also mean "start a chapter here".

2. The gesture budget (and the collision)

Every interaction the outline currently spends, and on what:

click chapter heading → collapse / expand
dblclick chapter title → rename
dblclick chapter intro → edit intro prose
hover chapter → actions → merge up · ungroup · include/exclude all
click block section → open the block's dock panel
dblclick block section → edit description
dblclick block name → rename block
hover block row → links → add block · (remove ✕ on the chip)
drag chip → gap between rows → reorder the block
drag chip → chapter heading → join that chapter
The collision. "Drop in the gap between chapters = new chapter" (variant C) targets a place that already has a meaning: every gap is a reorder target, and a chapter boundary is just a gap that happens to sit next to a heading. Resolving it needs a modifier key, an offset drop lane, or — cleanest — not using drag for creation at all.

A rule that resolves it

Drag changes where a block is; clicking changes what the chapters are. Drag stays purely about a block's position and membership (gap = order, heading = join). Every operation that creates, merges, dissolves or renames a chapter is a click affordance on the chapter row or the block row. No gesture carries two meanings, and the mental model is one sentence.

3. Creating a chapter — the remaining choice

A · boundary pill
A "split here" pill on the gap, visible on hover. Cost: puts a click target in the same place a drag drops — visually busy during a drag, though the meanings never fire together.
B · block link
"New chapter" beside "Add block" in the block's hover row: this block starts a chapter. Sits in a row that is already the home of block-scoped actions; no new geometry; no interaction shares its target. recommended
C · drag into gap
Elegant but collides with reorder, as above. Would need a modifier (Shift-drop) or a separate lane — both invisible. drop
D · chapter action "split below"
A fourth hover action on the chapter row, splitting after its first block. Cheap to add, but it can only cut at one fixed place, so it does not really express "start a chapter here".

The inverse pairs, once B is in

New chapter (block row) ⇄ merge up (chapter row) — add / remove a boundary
drag onto heading ⇄ ungroup — join / dissolve membership
include all ⇄ exclude all — bulk report flag

4. The two gaps worth closing next

Take a block out of its chapter. Today the only way is to ungroup the whole chapter. Natural fix, in keeping with the rule: give the block row a "no chapter" option — either a third link ("unchapter") or, since drag already owns membership, a drop target that means "belongs to no chapter". The latter reintroduces a drag target, so the link is safer.

Chapter order. Chapters have no order of their own — they are runs of the block order, so "move this chapter up" means moving all its blocks, which the DAG may forbid entirely. Two honest options: leave it derived (and let block reordering do the work), or offer "move chapter up" that attempts the block moves and refuses when illegal. Leaving it derived is the smaller lie.

5. Still open underneath

  • Stacks are one concept. Every operation here also rearranges the dashboard's dock tab-groups. Accepted deliberately; worth re-checking once real boards use it.
  • Split chapters (a stack whose blocks are not contiguous in the topological order) render as "(continued)" runs. Merge-up refuses across them; creation should too.
  • Empty chapters are not representable and should stay that way — a chapter is a run of blocks, not a container.
Proposal: adopt the rule, implement B, drop C. Drag keeps its two meanings (order, membership) and never gains a third; creation becomes a click link in the block row, next to "Add block", where every block-scoped action already lives; and "unchapter" joins it later as the missing inverse of "drag onto heading".
