Block description — how should prose look in the card?

The block-docs pilot (spec: _blockr.design/open/block-docs-code-quarto-pilot/) adds a markdown description per block that becomes the prose of the generated report. The pilot renders it as a plain accordion band. This page proposes dashboard-grade stylings. Same mock card everywhere: a scatter block with a two-paragraph markdown description.

Baseline — what the pilot ships today baseline

A fourth accordion section: white band, raw markdown render, checkbox and Edit link always visible. Functional, but it reads as a form, not as part of a dashboard.

A — subtitle caption combines with B or D

The description lives where every BI tool puts it: directly under the title, muted, clamped to two lines. Click expands. Reads as chart subtitle; zero extra chrome. Weakness: long markdown (lists, paragraphs) is cramped in the header; the clamp hides content by default.

B — docstring band recommended

A full-width tinted band between the header and the controls, with a quiet left accent: the visual grammar of a note or docstring. This is exactly where the prose sits in the generated report (heading, then text, then code and output), so the card mirrors the document. Full markdown fits. Edit is a pencil that appears on hover; excluded-from-report is dashed accent + dimmed + chip. Follows the settings-band precedent (gear-panel decision, variant B).

C — comment voice

Lean into the concept: the description IS the code comment, so style it like one. Monospace, italic, comment-green, a #' gutter. Charming and self-explaining for builders, and it visually matches the code sidebar. But in a consumer dashboard it reads as developer debris, and long prose in italic mono tires quickly.

D — figure caption combines with A

The description sits under the preview, styled like a journal figure caption: small, muted, with a lead-in. Report semantics for output-bearing blocks (the prose describes the figure). Weakness: for data or transform blocks there is no figure to caption, and prose that explains a decision reads oddly after the result it explains.

Recommendation: B as the base, A as the collapsed state. When the description section is toggled off, show the first line as a clamped subtitle (A) so the prose never fully disappears from a dashboard. When toggled on, the docstring band (B) shows full markdown, hover pencil to edit, dashed + chip when excluded from report. C stays the code sidebar's voice, not the card's. D can come later as an option for plot blocks once block types can choose a caption slot.

Mock chrome only approximates blockr.dock; spacing and icons are placeholders. Decision feeds the block-docs pilot spec (4-implementation, description section styling).
