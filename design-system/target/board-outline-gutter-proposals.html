Board outline, gutter layout

Revision of the two-pane outline (variant A, implemented on the pilot branch): instead of a separate rail card, each block's icon + title + switch live in a narrow left gutter, on the same grid row as its code section. Alignment is structural, so the hover wire disappears; the stack becomes a colored spine running down the gutter. The gutter takes 168px instead of the rail's 230px + gap, and nothing needs to scroll independently.

Interactive — hover pairs; flip a switch; the chip sticks while its section scrolls

What changes vs the implemented two-pane

  • Alignment replaces the wire. Chip and section share a grid row; the connector SVG and its geometry code go away. Hover still highlights the pair (the row's two cells).
  • The stack spine. The rail's group boxes become a thin colored line down the gutter spanning the stack's run, with the chapter heading (and its "N in report" pill) as the row above. Splits read naturally: the blue spine simply resumes at "(continued)".
  • Sticky chips. A chip is position: sticky inside its row, so on tall sections the block identity travels with the code.
  • Space. Gutter 168px vs rail 230px + 20px gap; no second scroll container, one scroll for the whole document. The sidebar could drop from 780px toward ~680px.
  • Cost. The rail as a compact stand-alone overview disappears: you can no longer see all blocks without scrolling through the code. If that overview matters, it can return later as a collapsed mode (sections folded to one line = the old rail, roughly).
Implementation note: the pilot's outline_ui() already iterates runs and blocks in one order; this is a re-template (grid with display: contents rows) plus CSS, minus the wire JS. The switch/toggle round-trip and section content are unchanged.
