Gear panel: same inputs, full width — four variants

Companion to design-system.html (§2.5, §3.4, drift #17). Question: should the gear popover keep its own control height (38px) and float in a 280px box — or reuse the exact controls of the normal block UI at full width, clearly separated? Every demo below is interactive: click the gear. All variants share one premise: the 38px tier and the popover-specific input styles are deleted; settings use the same 42/30/26 controls as everything else.

Why the floating popover is fragile beyond styling: it's position: absolute; z-index: 1000 inside dock panels — panels with their own stacking contexts and overflow, so a popover near a panel edge clips or lands under a neighboring card. An in-flow panel can't clip and needs no z-index at all. It also caps content at min-width: 280px, which is why it grew its own smaller 38px controls in the first place — width pressure created the extra height tier.

A — Current floating popover baseline

Anchored top-right, 280px min-width, own input recipe (.blockr-popover-input, 38px selects). Note how it covers the block's rows when open — the context you were configuring disappears.

B — Full-width inline band, pushes content down recommended

The gear expands a bordered, labeled band between the header and the block content — in flow, so rows slide down and stay visible. Controls are the standard ones: .blockr-text-input (42px), --bordered Select (42px), normal pills. Fields lay out with the flex-wrap idiom (flex: 1 1 160px), so the full width is actually used — settings sit side-by-side where the popover stacked them. Separation from block content = white bordered container + uppercase micro-label, against the grey rows.

Maximal reuse — but settings now look almost identical to data configuration, and the dashed divider carries all the separation. Best for blocks with 1–3 simple settings.

Recommendation: B — the full-width inline band. It's the only variant that scores on every axis except layout shift, and the shift is the point: "push the content down" keeps the rows you're configuring on screen, which is the context argument in favor of the gear pattern in the first place. The band is one small component (.blockr-settings, ~25 lines) that deletes three things: the 38px height tier, .blockr-popover-input, and the absolute-positioning machinery. Soften the shift with a 0.15s ease max-height transition (the sanctioned motion token). Keep --overlay (variant C) as a cheap modifier for the rare dense-dashboard case where shift is unacceptable — same markup, same controls, one class.

If B is adopted, the token outcome in design-system.html §2.5 simplifies further: the 42/30/26 ladder holds with no popover exception at all, and drift #17's "38px" row closes as "deleted, not folded". The .blockr-popover component itself stays only if something genuinely needs an anchored floater (e.g. the gear menu of a table header cell) — it should then contain menu items, never form controls.
