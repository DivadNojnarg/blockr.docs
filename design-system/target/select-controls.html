Select controls — the one select, systematically

The design system has exactly one select: Blockr.Select (blockr.dplyr/inst/js/blockr-select.js + css/blockr-select.css, shipped via blockr_select_dep()). Single and multi mode, searchable dropdown, label sublabels, removable + drag-reorderable tags. Every mock on this page uses the component's real classes. Decision 2026-07-22: this is the select everywhere — including two-choice pickers (the picker block); no shinyWidgets, no Bootstrap button groups, no bespoke pickers.

Single select

Closed shows the picked value with its label as a grey sublabel and a chevron. Open replaces the value with a search input and lists options; the current pick is bold, the keyboard row tinted. Placeholder state is grey-400 text. The bordered variant (42px, grey-50 fill, blue focus ring) is the standard inside blocks; the bare variant embeds in dense rows (filter conditions, join keys).

Multi select

Selections are tags inside the control: label, × to remove, drag to reorder (the blue drop indicator marks the landing). Open keeps the tags visible and appends the search input, so adding and pruning happen in one place. Selected options stay listed, bold. An empty option list shows the italic empty/loading row (setLoading supports lazy option fetch on first open).

Option anatomy + the label question

An option is {value, label}: the value renders primary, the label as the grey sublabel — the column-picker convention across blockr.dplyr. Open question for clinician-facing pickers (locked CDEX boards): pharma variable names are opaque (SYSBP vs "Systolic Blood Pressure"), so a labelPrimary display mode that swaps the two might be warranted. Not built; record demand before adding it — the sublabel already carries the human name.

Decision: blockr-select everywhere. Consistency beats per-count control types: no threshold cliff between 4 and 5 choices, one component to learn and maintain, and the multi mode's tags replace any pill/checkbox-button group. The picker block (blockr.viz, generalized from the measure switch) is the reference consumer: viewer control = single or multi Blockr.Select; its builder options (measures offered, allow multiple) sit in the gear settings band. The segmented/pill mocks in measure-switch-proposals.html are superseded as shipped UI and kept only as a possible future variant for locked flip-flop views.
