Titles, headings, and what the document inherits

Two questions tangled together: what we call a stack, and whether its title — and every block's title — automatically becomes a heading in the rendered report. The second is the consequential one: today a rename made for dashboard clarity silently rewrites the document.

1. The naming

A stack is blockr's organizational unit. People will use it for "the AE part", for scratch work, for things that simply belong side by side on screen. Only sometimes is it a chapter.

3. The four policies, and what each costs


A — everything becomes a heading what ships today


Stack → level 1, every included block → level 2. Predictable, no extra state. But a twenty-block
board emits twenty headings no analyst would have written, and the only way to change a heading is to
rename the block — which also renames its dock tab.



B — no automatic headings


Structure comes solely from markdown the author writes inside descriptions. Maximum freedom, and
closest to how quarto authors work by hand. But the outline's visible structure has no counterpart in
the output, and a casual user gets an unstructured wall. Turn both checkboxes off above to
see it.



C — defaults with an override


Heading text defaults to the title, but each stack/block may carry its own — stored beside the
description, in the same annotations map. Lets a block called adsl_filtered render as
Analysis population without renaming anything. The mock's "Analysis subset" block carries an
override; toggle "honour heading overrides" to see it apply.



D — asymmetric default recommended


Stacks head sections by default; blocks do not. A block's description flows as prose under
its section, and a per-block switch promotes it to a subsection when it earns one. This matches how
reports are actually shaped, and it makes the block-title coupling opt-in rather than automatic —
which is the part that currently misleads. It is the default state of the controls above.



E — level as a document property


Orthogonal to the rest: the document declares where its headings start. Stack = start level, block
= one deeper, and markdown inside descriptions is demoted to sit below that. The same board
then renders as a standalone report (#) or as one chapter of a larger document
(##) without touching a single title. Switch "start level" above.



The coupling to make visible either way. If titles feed the
document, renaming for dashboard clarity edits the report. Whatever policy wins, the outline should
show where a heading comes from — e.g. a muted "heading from title" hint on hover, and an
explicit override field once C exists.



The question underneath: is the outline the document,
or a view of it? Everything built so far assumes the former — which is why automatic headings
feel natural and the escape hatches are refinements. If it is a view, B is the honest answer and the
descriptions' own markdown is canonical.
