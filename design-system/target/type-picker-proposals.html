Type picker

Proposals for the chart-type selector in the ggplot block's main settings area — feeding the target settings-band concept (design-system.html §5.4). The current grouped strip inherits blockr.viz's family picker, which was designed for 3 groups of 2–4 types; with 9 types and one group it wraps raggedly and the left-hand group label hangs awkwardly.

Decided (2026-07-04): variant B (icon tile grid; with group headings for grouped types) — implemented in blockr.ggplot and blockr.viz's chart block (engine option typeTiles + typeIcon). Appendix: placement P1 (band under the gear header) with connector T1 (beak + active gear; shared opt-in class .blockr-settings--beak in settings-band.css). The main-vs-advanced question resolves by block role: authoring blocks (blockr.ggplot) show main config on the card with only chart-specific extras behind the gear (gear hidden when there are none); rendering blocks (blockr.viz) keep everything behind the gear — the rendered chart itself is the dashboard control, so dashboards show the control, not the config. The segmented strip remains for 2–4 type pickers (facet wrap/grid). Follow-up: the one-button Timeline group is folded into Individual — the heading describes data handling (rows plotted as-is vs self-aggregated), and gantt plots rows as-is; the timeline family (x/xend/y mappings) is untouched underneath.

Grouped types — the blockr.viz chart block

blockr.viz's picker has the extra dimension the strip was originally built for: 8 types in 3 families (Aggregated bar/pie/treemap/boxplot/radar, Individual scatter/line, Timeline gantt). Whatever replaces the strip must keep that structure visible, because the family decides which mappings exist. How each leading variant carries groups:

Appendix — where should the advanced band open?

Today the ggplot blocks open the gear band below the main settings (reading order: main, then advanced, then result). blockr.viz blocks open it directly under the gear header — but they have no always-visible main area, so both rules coincide there. The question only exists for blocks with a main area:

Notes
  • All three keep the gear active-state while open (blue tint) — the minimum signal that the same button toggles it off
  • T1 is the classic popover cue: near-zero cost, instantly readable
  • T2 makes gear + band literally one shape (a tab); strongest connection, slightly fussy at the rounded corner
  • T3 adds an explicit escape hatch for users who won't think to re-click the gear; title also removes the need for the band's uppercase heading
 
  • The beak must track the gear's x-position if the header ever gains more icons (fixed offset works today: the gear is always last on the right)
